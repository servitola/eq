# eq Round D — instrument knobs, events and hooks, CLI shape

Date: 2026-09-28. Status: approved in chat ("начинай"). Deltas on top of Round C.

## Why

Round D of `docs/research/00-roadmap.md`, reshaped by the first live try of the focus: the
user switched instruments with `[`/`]` and heard no difference. Focus is a lens and changes
nothing you hear. You only hear a change with `l` (solo), and a wide instrument such as voice
(85 Hz–9 kHz) isolates little. What the user expected is an instrument that can be turned up
or down. That becomes D1.

## D1 — instrument knobs (with the watch backlog it touches)

- Each instrument in `Zones.swift` gets one **character range**: the range a mixing engineer
  reaches for to bring that instrument forward. It is one of the ranges it already has, or a
  new one when none fits. The choice and the reason for it go into the table in the code.
  Examples: voice presence 2–5 kHz, kick thump 50–100 Hz, snare crack 4–6 kHz.
- **Knob:** a new per-profile layer, `"instruments": {"voice": 3.0}` next to `"preference"`.
  - Each set knob becomes one peak filter at the geometric centre of the character range.
  - Its Q comes from the range's width.
  - Its gain is the knob, −12…+12 dB, and `0` removes it.
  - Like preference, it costs nothing when unset.
  - Presets carry it, `eq flat` drops it, `eq export` writes it as peak filters, and
    undo/history work through ConfigStore as usual.
- **CLI:** `eq boost <instrument> <gain> [--device DEVICE]` and `eq boost` alone lists the
  knobs. `eq` prints a `boost: voice +3 kick -2` line when any is set. `--json` works as
  everywhere.
- **Watch:**
  - While focused, `→`/`←` raise/lower the focused instrument's knob by 0.5 dB. The same
    keys, unshifted, are `.`/`,`, and on a Russian layout `ю`/`б`.
  - The header shows `voice +3.0`.
  - The bracket row marks the character range as the bright one.
  - `l` now solos the **character range**, the range the arrows turn, instead of the outer
    span. This fixes the BACKLOG item "wide instruments isolate little".
  - The hint box and README key table gain the arrows.
- **Backlog items fixed in the same area:**
  - Keys work while no frames arrive: poll the socket and stdin together.
  - Esc then `[`/`O` in the same read no longer swallows the next key.
  - A refocus while the device settles at 0 Hz does not leave "listening" without SOLO.
- **Honest limit (README):** a knob cannot split instruments that share a range. Boosting kick
  thump also lifts the bass there. Say so in one sentence.

## D3 — `eq events` and hooks

- **`eq events`:** JSON lines on stdout until Ctrl-C, one object per state change, never on
  meter ticks.
  - Shape: `{"t":…,"event":"device"|"rate"|"profile"|"enabled"|"solo"|"daemon", …fields}`.
  - A `profile` event means the curve, preset or knob changed.
  - The events come from the daemon over the existing socket, as a separate message kind.
    Subscribing must not start the meter DSP or the 30 Hz timer.
  - The command exits 1 when the daemon is not running or predates this.
- **Hooks:** `"hooks": {"device": "<shell command>", "preset": "<shell command>"}` at the top
  of `eq.json`.
  - The daemon runs a hook with `/bin/sh -c` off the audio thread, with `EQ_DEVICE`,
    `EQ_PRESET` and `EQ_RATE` in its environment and a 10 s timeout.
  - Stdout and stderr go to the log, capped. A failure is logged and never affects audio.
  - `eq doctor` reports hooks that point at a missing executable when that can be told.

## D2 — CLI shape (after D1 and D3 are merged)

- **Noun groups:** `eq device list|use|copy`, `eq preset …`, `eq filter …` and `eq import …`.
  `set/preamp/flat/on/off/bass/treble/tilt/boost/undo/redo` stay top-level. Every old spelling
  keeps working as an alias, so nothing breaks.
- Rename the device placeholder `Q` to `DEVICE` everywhere, and accept `copy --device` next to
  `copy --to`.
- **`--dry-run`** on every state-changing command: print what would change (before → after, in
  the same painted form as `eq`) and write nothing. Exit 0.
- **Completions and man page** come from the same command table as `--help`:
  - `eq completions zsh|bash|fish` prints the completion scripts, which complete device
    names, presets, instruments and formats.
  - `eq man` prints a roff man page.
  - The cask installs them with its `zsh_completion`/`bash_completion`/`fish_completion`/
    `manpage` stanzas from files that the publish script generates into the bundle.

## Dropped from the roadmap, with reason

- **JSON envelope** `{schemaVersion, command, data}`: it breaks every `jq` line in the README
  and every script already written against `--json`, and nobody consumes a schema version.
- **`eq://` URL scheme:** the bundle is a CLI/daemon with no NSApplication event loop to
  receive Apple Events. Shortcuts already runs `eq` through "Run Shell Script".
- **`eq debug`:** there is nothing to put in it yet.
