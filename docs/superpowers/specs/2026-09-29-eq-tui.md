# eq tui — one full terminal UI, `eq watch` becomes its meter view

Date: 2026-09-29. Status: draft for the user's review; not approved. Research:
`docs/research/08-tui.md` (the current watch inventoried, Bubble Tea / Bubbles / Lip Gloss,
ratatui / crossterm, Textual, lazygit, k9s, btop, htop, gitui, bottom read at source, and what
Darwin offers a zero-dependency Swift program).

## The request, and how this spec reads it

The request: "our TUI, `eq watch` and `eq watch --zones`: I want to show those from inside it
too; the legend that helps navigate should not disappear so fast; I want the TUI normal and
full-fledged, and also an `eq tui` command. Look at how the best TUIs are built and make ours
like that."

How this spec reads it (to confirm):
- **"Show those from inside it."** The instrument strip is already a toggle (`z`) inside the
  watch, but nothing on screen says so once the key box is gone, so it reads as a start-up flag
  only. Inside the TUI, the strip, the instrument table that `eq zones` prints and the knobs that
  `eq boost` lists are all one keystroke away, and the keybar always names that keystroke.
- **"The legend disappears too fast."** Two measured causes in `Watch.run`: the box hides after
  240 frames (8 s at 30 fps, `Watch.hintFrames`), and *any* key hides it at once (`hintLeft = 0`
  on the first line of `handle`). The one-line compact hint is gated by the same counter, so on a
  narrow terminal the legend vanishes too. Fix: a keybar on the bottom row that never hides, plus
  a full help overlay on `?` that stays until it is closed.
- **"Full-fledged, and an `eq tui` command."** One program with views for everything the CLI
  can do to a curve, a device, a preset, an app rule and the audio path, a command palette that
  runs any `eq` command, and `eq watch` kept as the same program opened on the meter.
- **"Like the best TUIs."** Their architecture, not their dependencies: eq stays zero-dependency
  (the decision that already ruled out swift-argument-parser). The framework is small and
  in-repo; section "Why no dependency" weighs the existing Swift TUI libraries.

## What the user sees

```
 BE-RCA · 44.1 kHz · preamp -1.5 dB · favourite* · night comp -2.1 · peak -6.0 dB        LIMIT
 Meter  Tune  Instruments  Filters  Presets  Devices  Apps  System  Events  History
                                       (the view)
 saved: band 1 kHz -3.0 dB                                                   ← message row
 1…0 band  ⇧ down  +− preamp  z zones  [ ] focus  ← → knob  l listen  g go  : cmd  ? keys  q quit
```

Four rows belong to the shell, the rest to the view:
1. **Status line**, always: the meter header as today (device, rate, preamp, preset with `*`,
   bass/treble/tilt, knobs, comp with live reduction, colour, peak, focus, SOLO/BYPASS/LIMIT),
   with the same right-to-left dropping rules (`Watch.header`). It shows in every view, so a
   preset applied in Presets is heard and seen at once. The live parts (peak, LIMIT, comp
   reduction) come from meter frames and show only while the meter connection is open (see
   "Event loop"); elsewhere the line is built from the events stream and the config.
2. **Tab row**: the ten views; the current one bold and underlined, each with its go-to letter in
   the accent colour. Hidden below 14 rows; below 60 columns it shows only the current view and
   `g go`.
3. **Message row**: the note, error or prompt of the moment (today's footer notes, `save as:`,
   `outside voice — Esc to unfocus`, "daemon gone — reconnecting"), empty otherwise. It is always
   reserved, so a note appearing never moves the meter by a row.
4. **Keybar**, always: the keys of the focused view and mode, most useful first, whole entries
   dropped from the right to fit, `? keys` and `q quit` always kept (the rule
   `HintBox.compact` already follows). In a modal it shows that modal's keys (`Enter save · Esc
   cancel`). Nothing ever hides it; there is no timer.

`?` (and `h`, and `р`) opens the **help overlay**: every key of every context, grouped (this
view, global, go-to, palette), with its long description, scrollable, `/` filters it. It stays
until `?`, `Esc` or `q` closes it. The old box, its 8 s timer and the `x`/`watch-hint-off` marker
retire: the keybar replaced what the box was for. The marker file is left alone and ignored.

### Views

| Key | View | What it shows and does | Built on |
| --- | --- | --- | --- |

| `g t` | **Tune** | the profile as one editable strip: ten bands as vertical sliders with a band cursor, preamp, bass, treble, tilt, compressor, colour; a mini meter row under the sliders | `WatchSession`, `Profile` |
| `g i` | **Instruments** | `eq zones` and `eq boost` as one table: instrument, ranges in Hz, bands touched, knob gain; `Enter` focuses it in Meter, `←→` knob, `l` listen | `Instruments`, `InstrumentTable` |
| `g f` | **Filters** | the numbered filter list (`eq filter list`); add, edit in a small form (type, freq, gain, Q), remove with confirm | `filter` code paths |

`g` alone opens a small which-key menu over the keybar listing these letters (helix/emacs
which-key; lazygit's and k9s's view menus do the same job). A tab is also a mouse click target.
`Esc` with nothing to cancel goes back to the previous view (a view stack, as k9s pages);
`eq tui <view>` opens a view directly (`eq tui presets`); `eq watch [--zones]` is `eq tui meter
[--zones]`.

### Keys

Three layers, searched top-down: **modal** (prompt, form, confirm, palette, help, which-key),
**view**, **global**. A key a modal owns never reaches the view: that is how `s` turning into
a text prompt already works, generalised.

Global, in every view:

| Key | Action |
| --- | --- |
| `g` + letter | go to a view (menu shows the letters) |
| `:` , `ж`, `Ctrl-P` | command palette |
| `?`, `h` | help overlay |
| `u` | undo this session's last change (unchanged meaning) |
| `q`, Ctrl-C | quit (`q` inside a text field types a `q`) |
| Ctrl-Z | suspend to the shell; `fg` brings the screen back as it was |

Meter keeps every key it has today with the same meaning: `1…0`, Shift+digit, `+ − = _`,
`b B t T`, `p ↑ ↓`, `c v V`, `u`, `s`, `z`, `] Tab [`, `→ ← . , > <`, `Esc`, `l`, `q`, and the
Russian letters on the same physical keys. Two changes: `x` no longer does anything (the box it
dismissed is gone), and `h`/`?` open the overlay instead of the box.

Tune: `← →` move the band cursor over bands, preamp, bass, treble, tilt, comp, colour; `↑ ↓` step
0.5 dB (or the next mode/amount); `⇧↑ ⇧↓` step 3 dB; digits keep their Meter meaning (band
steps); `Enter` types an exact value in the message row; `Del`/`Backspace` sets the selected
control to 0 or off. This is the layout-proof way to lower band 7 from a Russian layout, which
Shift+7 cannot do today (it types `?`).

List views (Instruments, Filters, Presets, Devices, Apps, History, Events) share one list
binding set: `↑ ↓` (and `j k`, `о л`) move, `PgUp PgDn Home End`, `/` filter, `Enter` the
primary action, `a` add, `r` rename or edit, `d` delete behind a confirm, `Esc` clears the
filter, then goes back.

Mouse (SGR 1006, enabled only in the TUI): click a tab to switch; click a band column in Meter
or Tune to select it; the wheel over a band steps it 0.5 dB; click a list row to select it,
double-click for its primary action. Every mouse action has a key; the mouse is never the only
way. `EQ_NO_MOUSE=1` leaves the terminal's own selection alone.

### Command palette

`:` opens a one-line prompt in the message row with suggestions above it, fuzzy-matched, taken
from two tables: every `eq` command form from `CommandHelp.all` (the table that already makes
`--help`, the man page and the three completion scripts), and every TUI action that has a name
(`go presets`, `zones`, `listen`, `bypass`). Operands complete from the same `Completions.Kind`
values the shells use (devices, presets, instruments, bands, formats, apps). `Enter` runs it;
`Tab` accepts a suggestion; `↑` walks the palette's history (kept in `~/.cache/eq/tui-history`,
100 lines). An `eq` command runs as a child process (`eq <args>`) whose output, colours kept,
appears in a result pane that `Esc` closes; the TUI keeps drawing while it runs, and `Ctrl-C`
in the pane stops it. The child gets `CLICOLOR_FORCE=1` and `COLUMNS` set to the pane width;
`Paint.enabled` and `LiveTerminal.width` learn to honour both (two conditions), since the child's
stdout is a pipe. Streaming commands (`watch`, `stream`, `events`, `tui`) are refused with
a pointer to the view that does it.

### What keeps working exactly

- `eq watch` and `eq watch --zones`: same screen, same keys, same exit codes (0 on `q`, 1 when
  the daemon closed the socket), plus the tab row, message row and keybar.
- Every edit goes through the same code as today (`WatchSession.apply`, the CLI's `editProfile`
  paths), so one TUI session is still one `eq undo` step, and `u` walks back inside it.
- Solo semantics: owned by the TUI's meter connection, cleared on `l`, `Esc`, quit, crash or a
  dropped socket, never saved.
- Colour rules: the sixteen colours with one meaning each; `NO_COLOR` and `TERM=dumb` give a
  monochrome TUI where glyphs, bold, underline and reverse carry the state (the current tab is
  reverse video, the selected row too).

## Architecture

### Shape: the Elm architecture, as Bubble Tea and ratatui's recommended app pattern do it

```
            ┌────────── Runtime (EQTerm) ──────────────────────────────────┐
 stdin ────►│ InputDecoder ─┐                                              │
 meter.sock►│ LineReader ───┤                                              │
 events ───►│ LineReader ───┼─► Msg ─► update(inout Model, Msg) -> [Cmd] ──┼─► effects: save, send,
 child fds ►│ ChildReader ──┤                    │                         │   spawn, connect, timer,
 signals ──►│ self-pipe ────┤                    ▼                         │   quit
 timers ───►│ deadline ─────┘          view(Model, Size) -> Screen         │
            │                                  │                           │
            │                     Renderer: diff(front, back) -> bytes ────┼─► stdout (one write)
            └──────────────────────────────────────────────────────────────┘
```

- **Model**: one struct, value type — current view and view stack, meter state (last frame,
  focus, strip, listening, flash), the header snapshot, each view's selection and scroll, the
  modal stack, the message, the connection state. No terminal handle inside.
- **Msg**: an enum — `key(Key)`, `mouse(Mouse)`, `paste(String)`, `frame(MeterFrame)`,
  `event(EventLine)`, `resize(Size)`, `tick(Timer)`, `childOutput(id, bytes)`, `childExit(id,
  status)`, `connected(Socket)`, `disconnected(Socket)`, `suspend`, `resume`.
- **update** is a pure function: `(inout Model, Msg) -> [Cmd]`. It never touches a file or a
  socket.
- **Cmd**: an enum of effects the runtime performs and reports back as Msgs — `edit(WatchAction)`
  (through `WatchSession`, in-process: a config save is a few ms), `send(String)` (solo),
  `spawn(argv)`, `connect(.meter | .events)`, `disconnect(.meter)`, `after(Duration, Timer)`,
  `refreshHeader`, `quit(code)`. Bubble Tea's `Cmd`/`Msg` split, without goroutines: there is one
  thread.
- **view** is a pure function `(Model, Size) -> Screen`, where `Screen` is a grid of cells. No
  escape codes leave a view; only the renderer writes bytes.

Why this and not the obvious alternative (grow `Watch.run`'s closures): `Watch.run` is already a
hand-rolled update loop — 13 captured `var`s and 8 nested functions over one `source.lines`
callback — and it is where the hard bugs lived (solo re-requests across rate changes, Esc
timing, keys while frames stop). Ten views on that shape would multiply the captured state. A
pure `update` gives each of those bugs a one-line test: a Msg sequence in, a Model and a Cmd
list out, which is what `WatchLoopTests` already approximates with fake sources.

### Event loop: one thread, one `poll`

The runtime waits in `poll(2)` on stdin, the meter socket, the events socket, every running
child's stdout/stderr, and a self-pipe that signal handlers write one byte to; the timeout is the
nearest timer deadline. This is what `MeterClient.lines` already does for two descriptors (stdin
and the meter), grown to N; `DispatchSource` would work too but pulls in a run loop and a second
thread for no gain at this scale (SwiftTUI does it that way, research §5), and `poll` keeps the
loop single-threaded — `update` never races a render — and testable by feeding it pipes.
crossterm's Unix backend is the same design: one kqueue over the TTY, a SIGWINCH pipe and a waker.

- Frames: all complete lines read in one wakeup are decoded, only the last is kept (a slow
  terminal must not build a backlog; the daemon sends 30 a second whatever we do).
- Render: after a wakeup that changed the Model, at most once per 1/60 s (a key between frames
  draws at once, as today). The meter drives the rate; Presets with no meter draws only on
  change, so an idle TUI on a list view costs ~0 CPU.
- Esc: decided by byte availability, not a clock, as `KeyBuffer` already does and as crossterm,
  termbox2 and notcurses do (research §3.3): a read that ends in a bare `ESC` is followed by one
  zero-timeout re-poll, and if that brings nothing the key is Esc. Today the "next read" is the
  next frame or the 0.1 s idle wake-up, which on views without a meter would make Esc feel slow.
- Reconnect: EOF on the meter or events socket shows "daemon gone — reconnecting" in the message
  row and retries at 0.5, 1, 2, 4 s (cap 4 s). Config edits keep working meanwhile; the daemon
  applies them when it returns. `eq watch` keeps its old contract (exit 1 on EOF) unless run as
  `eq tui`.
- The meter connection is held only while a view that shows live levels is on screen (Meter,
  Tune) or a solo is active, so the daemon's meter DSP stops when the TUI sits on Presets — the
  "zero cost while nobody watches" rule of v4 kept per view. The events connection is held from
  start to end. That is two of the daemon's eight client slots.

### Terminal lifecycle

`Terminal.enter()` and `Terminal.leave()` are the only places that change terminal state, and
every exit path reaches `leave`:
- enter: save termios; raw mode (`ICANON ECHO IEXTEN` off, `ISIG` off so Ctrl-C and Ctrl-Z arrive
  as keys and quit/suspend go through the loop); alternate screen `?1049h`; cursor hidden
  `?25l`; bracketed paste `?2004h`; mouse `?1000h ?1002h ?1006h` unless `EQ_NO_MOUSE`; focus
  events `?1004h` (redraw on focus-in, since some terminals drop our last frame when hidden).
- leave: the same in reverse, then restore termios (raw mode off before leaving the alternate
  screen, the order ratatui's `restore` keeps). It is written as one precomputed byte string
  and one `tcsetattr` so it is async-signal-safe.
- Normal quit, a thrown error, `SIGTERM`, `SIGHUP`, `SIGINT` from `kill`: handler writes to the
  self-pipe, the loop leaves cleanly (solo off, sockets closed).
- **Crash**: a Swift trap on arm64 is `brk` → `SIGTRAP`; a bad pointer `SIGSEGV`/`SIGBUS`; an
  abort `SIGABRT`. `sigaction` handlers for those run the async-signal-safe `leave`, reset the
  signal to default and re-raise, so the crash report is still written and the shell is usable —
  htop's `CRT_handleSIGSEGV` and btop's `_crash_handler` do exactly this (research §2.3).
  Today only SIGINT/SIGTERM restore (`restoreTerminalAndExit`), and `padded` exists only because
  "a trap bypasses every terminal-restore path".
- **Suspend** (BACKLOG: "Ctrl-Z in eq watch leaves the alternate screen up"): Ctrl-Z arrives as
  byte 0x1A; the loop leaves the terminal, drops the meter connection only if no solo is on, sets
  SIGTSTP to default and `kill(0, SIGTSTP)`; on `SIGCONT` it enters again and forces a full
  redraw — Bubble Tea's `suspend()` (release, SIGTSTP, restore, `ResumeMsg`). An external
  `kill -TSTP` goes through the same handler.
- **Resize**: `SIGWINCH` → self-pipe → `resize` Msg with the `TIOCGWINSZ` size, then a full
  redraw (the front buffer is invalidated). Today the size is polled every frame, which misses a
  resize while frames stop.

### Rendering: cell buffer and diff

- `Screen`: `width × height` cells, each `(text: a grapheme cluster, width: 0|1|2, style)`, where
  `style` is foreground (one of the sixteen colours or default), `bold`, `dim`, `underline`,
  `reverse`. A wide cell's right half is a continuation cell. That is ratatui's `Buffer`/`Cell`.
- The renderer keeps the last screen it wrote (front) and diffs the new one (back) cell by cell;
  a run of changed cells on a row is written with one cursor move (`CSI row;col H`) and the
  minimal SGR changes; unchanged rows cost nothing. Each frame is one `write(2)` wrapped in
  synchronized-update brackets (`CSI ?2026h` … `CSI ?2026l`), which terminals that support it use
  to avoid tearing and others ignore. btop wraps every frame unconditionally and writes it once;
  ratatui leaves the brackets to the app; Bubble Tea's HEAD dropped its line renderer for a cell
  buffer with touched-cell diffing (research §2.2, §3.1).
- Today every frame rewrites every line in full with `ESC[K` and `ESC[J`
  (`Watch.run`'s `draw`). The meter changes most cells of the bar area every frame, so the win is
  in the header, labels, gains, strip, tab row and keybar, which are static between edits, and in
  every view without a meter, which becomes nearly free.
- Width: our own glyphs are all one column (`█▁…▇░▬━┌─┐│⇧←→…`). Device, preset and app names are
  user text. Width per grapheme: ASCII fast path; `wcwidth(3)` from Darwin's libc for single
  scalars, after `setlocale(LC_CTYPE, "UTF-8")` at start — without it Darwin's `wcwidth` returns
  −1 for every non-ASCII character, and `""` fails the same way when `LANG` is unset (measured,
  research §4); 2 for a scalar with `isEmojiPresentation` or a cluster with U+FE0F; 0 for combining
  marks (`generalCategory` `Mn Me`) and ZWJ continuations; a width is per grapheme cluster, never
  a sum over its scalars. A name that would split a wide glyph at the edge is cut one column earlier and
  padded.
- Colour: the sixteen-colour palette only (no truecolor), so no colour-profile detection is
  needed beyond today's `Paint.enabled` rule (`NO_COLOR`, `TERM=dumb`, not a TTY).

### Layout and widgets

- **Layout**: a `Rect` split along one axis by constraints `.fixed(n)`, `.min(n)`, `.fill(weight)`,
  `.percent(p)` with a one-pass solver (fixed and min first, the rest by weight). ratatui's
  Cassowary solver is more than ten views of rows and columns need; `WatchLayout.fit` stays as the
  meter's own internal layout, since its rules (meter floor 4, bracket before strip) are domain
  rules, not box rules.
- **Widgets**, each a pure `draw(into: inout Screen, rect: Rect, state)`:
  `Text` (styled spans, truncate/ellipsis by width), `Tabs`, `Keybar`, `List` (selection, scroll,
  filter, `StatefulWidget`-style state kept in the Model), `Table` (columns by constraint),
  `Slider` (vertical, for Tune), `Meter` (the bars, from `Watch.frame`'s logic), `Strip` (from
  `Strip.row`), `Modal` (centred box with a title), `TextField` (cursor, backspace, word delete,
  paste, from `Watch.promptStep`), `Confirm`, `Form` (fields of the four filter kinds), `Help`
  (grouped key table), `Log` (Events, command output). `AnsiText` turns a child's coloured output
  into cells (SGR subset: the codes `Paint` writes and `0`).

### Keymap as data: one table drives handling, keybar, help, palette, README and man

```swift
struct Binding {
    var action: Action          // what update receives
    var keys: [Key]             // .char("z"), .ctrl("p"), .arrow(.up), .shift(.arrow(.up)), .f(1)
    var context: Context        // .global, .view(.meter), .list, .modal(.prompt), …
    var bar: String?            // short keybar label ("zones"); nil = not on the bar
    var rank: Int               // keybar order and drop priority; 0 = pinned (? and q)
    var help: String            // the long text for the overlay, README and man
    var group: String           // heading in the overlay
    var palette: String?        // name in the command palette ("toggle zones")
    var when: ((Model) -> Bool)? // shown and live only in this state (l only with a focus)
}
```

This is the one pattern every studied TUI shares (research §2.4, §3.5): Bubbles' `key.Binding`
matches keys and renders short/full help from the same value; lazygit's options bar is the
focused context's bindings plus the global ones whose key the context does not shadow, filtered by
`DisplayOnScreen`, and its `?` menu and docs cheatsheet come from the same list, the latter checked
by a test; gitui walks one `CommandInfo` list once for the bar (`quick_bar`) and once with
`force_all` for the help popup; k9s' hint header is always on screen and marks keys shared by every
view so they are not repeated per view. eq takes lazygit's composition rule for the keybar and
gitui's two projections, and adds the palette and the README as a third and fourth.

- The **Russian layout** stops being hand-listed per key. One table maps the physical keys of the
  US layout to the Russian one (`qwertyuiop[]asdfghjkl;'zxcvbnm,./` ↔
  `йцукенгшщзхъфывапролджэячсмитьбю.`, and the shifted rows); a `Key.char` binding matches its
  Russian twin automatically. The known collisions are declared, not accidental: Russian Shift+7
  is `?` (help wins, as today) and Russian Shift+6 is `:` (palette wins; band 6 is then lowered
  from Tune with `↓`, or with `^` on a US layout). A test fails when a new binding's twin
  lands on another binding in the same context.
- `WatchKeys.action(for:)` and `HintBox` become projections of this table; the table is checked by
  tests: no two bindings in one context share a key, every action has a key, every bar label fits
  12 columns, the README "Keys" section equals the generated one (as `HelpTests` checks forms
  against `CommandHelp.all`).
- The man page gets a KEYS section generated from the same table (`ManPage.swift`).

### Module layout

```
Sources/EQTerm/          new target, knows nothing about audio (≈1.6–2.0k lines)
  Terminal.swift         termios, modes, enter/leave, signals, self-pipe, size
  Input.swift            bytes → Key/Mouse/Paste (KeyBuffer and WatchKeys' CSI/SS3 parser, grown:
                         modifiers `CSI 1;2A`, SGR mouse `CSI < b;x;y M/m`, `CSI 200~` paste, F-keys)
  Loop.swift             poll over fds, timers, child processes; Program<Model, Msg, Cmd>
  Screen.swift           Cell, Style, Screen, width
  Renderer.swift         diff + SGR + synchronized update; full redraw on resize/resume
  Layout.swift           Rect, constraints
  Widgets/*.swift        Text, Tabs, Keybar, List, Table, Modal, TextField, Help, Log, AnsiText
  Keymap.swift           Binding, Key, layout twins, lookup, keybar fitting
Sources/eq/TUI/          the app (≈2.0–2.5k lines)
  Model.swift, Msg.swift, Update.swift, Effects.swift (WatchSession, spawn, sockets)
  Keys.swift             the one binding table
  Views/Meter.swift …    one file per view
Sources/eq/CLI/Watch.swift   shrinks to `eq watch` → `eq tui meter`, plus the frame code the Meter
                             view reuses until it is ported
```

A separate target keeps the boundary honest (EQTerm cannot reach `Config`) and its tests fast;
the package already has two library targets (`EQAtomics`, `EQCore`).

### Why no dependency

The zero-dependency decision holds. Research §5: the Swift options (SwiftTUI, TermKit,
ANSITerminal) are either SwiftUI-style declarative frameworks whose update model does not fit a
30 fps socket-driven meter, large (TermKit), or thin escape-code helpers that save less than a
day. The parts that are genuinely hard — the input decoder and the terminal restore — are
already written and tested in eq (`KeyBuffer`, `WatchKeys`, `LiveTerminal`, 424 lines of key
tests). What is left to write (cell buffer, diff, layout, a dozen widgets) is ~2k lines of code
whose behaviour we can pin with golden tests.

## Testing

- **update**: Msg sequences → Model and Cmd assertions. Every `WatchLoopTests` and `FocusTests`
  case is re-expressed this way before the old loop is deleted, and must pass unchanged in
  meaning.
- **view**: golden screens — `view(model, size)` rendered to plain text (and a styled variant with
  `[g]…[/]` markers) compared with files in `Tests/eqTests/Fixtures/tui/`, at 80×24, 120×40,
  40×12, 20×8. The meter view's first golden set is produced from today's `Watch.frame`, so the
  port is proven pixel-equal (modulo the shell rows).
- **renderer**: diff of two screens → exact byte string; a changed cell in the middle of a wide
  run; a style-only change; resize invalidates; the bytes applied to an in-test terminal emulator
  (`AnsiText` applied to a grid) reproduce the back buffer — a property test over random screens.
- **input**: today's 424-line `WatchKeysTests` move to the decoder, plus modifiers, mouse, paste,
  split reads, a lone Esc decided by the zero-timeout re-poll.
- **terminal**: a child process on a pseudo-terminal (`openpty` from Darwin) enters, then exits
  by `q`, SIGTERM, SIGTSTP/SIGCONT and a forced trap; the pty's termios and the last bytes read
  must show raw mode off, cursor visible, alternate screen left.
- **keymap**: the table checks listed above.
- **performance**: a benchmark renders 300 meter frames at 120×40 and reports bytes written and
  CPU time; the budget is below.

## Performance budget

Measured first (M1) on this Mac with the daemon playing music, 60 s, `ps -o %cpu` sampled once a
second: `eq watch` at 120×40 today, and bytes per frame via a tee of stdout. Budget for `eq tui`

## Risks

- **Scope.** Ten views is a product, not a feature. M1 alone answers the request; M2 is the
  investment; each later view is optional and ordered by use. Stop after any milestone.
- **Terminal variety.** The user runs Zap (a Warp fork) inside tmux 3.7 (`escape-time 10`).
  Synchronized output, SGR mouse and focus events inside tmux need checking on that stack in M2;
  every one of them degrades to "works, maybe with a flicker" when unsupported. Ctrl-P under a
  Russian layout: whether the terminal sends 0x10 is unverified; `:` and `ж` do not depend on it.
- **Two sockets.** The events socket takes a second of the daemon's eight client slots; two TUIs
  plus a `stream` and a hook runner is still well under the cap.
- **Child processes** (palette, `eq mode`, `eq import` over the network) must never block the loop
  and must die with the TUI: they run in their own process group, which the TUI kills on exit.
- **Mouse capture** takes the terminal's text selection away (Shift-drag still selects in most
  terminals); `EQ_NO_MOUSE=1` turns it off.
- **Swift traps in a signal handler context**: the crash handler must use only `write`,
  `tcsetattr`, `signal`, `raise`. A test proves it on a pty.

## Open questions for the user

1. **Scope**: M1 alone (keybar that stays, help overlay, zones and the instrument table inside,
   `eq tui` as a name), or commit to M2–M6 as well? M2 is the architectural step; after it every
   view is a few hundred lines.
2. **Russian Shift+6**: `:` opens the palette on both layouts, which takes "lower band 6" away
   from Russian Shift+6, as `?` already took band 7. Band 6 stays lowerable from Tune (`↓`), with
   `^` on a US layout, and with `ж` still opening the palette. Acceptable, or should the palette be
   `ж`/Ctrl-P only on a Russian layout, leaving `:` to band 6?
3. **Mouse on by default**, with `EQ_NO_MOUSE=1` to turn it off — or off by default, since a
   mouse-capturing TUI breaks copying text out of the terminal without Shift?

## Decisions (2026-09-29)
1. **Scope:** all of M1–M6.
2. **Palette key:** the same physical key on every layout. That is the key right of L, which
   types `;` on US and `ж` on Russian: `;` and `ж` open the palette, and so does Ctrl-P.
   `:` is not bound to the palette, because on a Russian layout it is Shift+6 and stays
   "lower band 6". Every binding follows this rule: one physical key, derived from the
   physical-key table, with collisions declared.
3. **Mouse:** the user wants it if it gets in the way of nothing. Mouse reporting takes over
   plain drag-to-select, so it is **off by default**. `m` toggles it in the TUI, the
   `tui.mouse` setting in eq.json remembers the choice, and the keybar shows its state.

## Visual design

Added 2026-09-29 after the user saw M1: "not bad, but too few colours and too little detail; it
needs the feel of a luxury panel", then "the dense graphic look is great, and a living
mixing-desk look is interesting too — make them selectable". Research:
`docs/research/09-tui-look.md` (terminal programs read at source, the user's tmux and font
measured, hardware metaphors, a byte simulation). Mocks: `docs/design/tui/*.ans`, all of them in
`docs/design/tui/preview.html` (look / screen / colour-depth switcher); regenerate with
`python3 docs/design/tui/mocks.py [--bytes]`.

This section replaces the "Colour" bullet of "Rendering" (sixteen colours only) and extends the
cell `style` with 256 and 24-bit colours and a background.

### Three looks

| Look | What it is | Meter | Default palette |
| --- | --- | --- | --- |
| `studio` (default) | dense and graphic: rounded panels, a status bar of segments, bars coloured by level with a gradient by height, peak-hold ticks, the EQ response drawn over the bars in braille with the boost and cut areas tinted, a dBFS scale left and a gain scale right, gain chips, and at ≥ 110 columns a side column of gauges (output peak and limit, compressor gain reduction, colour amount, bass/treble/tilt, instrument knobs) | `bars` | `ink` (dark), `paper` (light) |
| `console` | a mixing desk: one channel strip per band with a paper label, an LED ladder whose unlit segments stay faintly visible, an amber readout, a fader whose cap sits at the band's gain; a header rail with lamps (SOLO, BYPASS, LIMIT) that are always there and light up; at ≥ 110 columns a master section with a backlit gain-reduction window and needle, compressor lamps, peak readout, preamp slider and knobs for tone and instruments | `leds` | `brass` |
| `classic` | today's screen in the terminal's own sixteen colours: bars take the band's gain colour, `▬` marks the slider, `░` the input ghost | `bars` | the terminal's |

Every look draws every view; a look changes glyphs and colours, never what a view shows or
which keys it takes. Below 60 columns or 12 rows, `studio` and `console` fall back to the
`classic` layout in their own colours (the side column and master section need the room).
`NO_COLOR` keeps the chosen look in monochrome (below).

### Parameters

| Setting | CLI (`eq tui`, `eq watch`) | `eq.json` | Values | Default |
| --- | --- | --- | --- | --- |
| look | `--look NAME` | `tui.look` | `studio`, `console`, `classic` | `studio` |
| palette | `--palette NAME` | `tui.palette` | `auto`, `ink`, `paper`, `brass` | `auto`: the look's default; `paper` when the terminal answers OSC 11 with a light ground |
| colour depth | `--colors DEPTH` | `tui.colors` | `auto`, `24bit`, `256`, `16`, `none` | `auto` (detection below) |
| meter style | `--meter STYLE` | `tui.meter` | `auto`, `bars`, `leds` | `auto`: the look's |
| response curve | `--curve` / `--no-curve` | `tui.curve` | bool | on (`studio`), off elsewhere |
| scales | `--scale` / `--no-scale` | `tui.scale` | bool | on |
| peak hold | `--peaks` / `--no-peaks` | `tui.peaks` | bool | on |
| ground | `--background terminal\|theme` | `tui.background` | `terminal`, `theme` | `terminal` |

- Precedence: flag > `eq.json` > default; `NO_COLOR` and `TERM=dumb` beat all of them (they
  force `none`, the look stays). A flag applies to that run only; a key press saves.
- Keys (Meter and every view, global layer): **`y`** next look (`studio → console → classic`),
  **`Y`** next palette of this look; Russian `н`/`Н`, the same physical key. Both save to
  `eq.json` as `m` saves `tui.mouse`, show on the keybar as `y look`, and are in the help overlay
  under "Look". `y` is free in every context today (`Keys.swift`).
- `--colors`, not `--color`: `eq color` is the tape/tube colour stage, and a `--color` flag on the
  TUI would read as that.
- No `braille` meter style: eighth blocks already give 8 steps per row, braille only 4; braille
  earns its place for the curve, where its 2 columns a cell matter.
- `tui.background theme` paints the palette's ground under everything; `paper` on a dark
  terminal needs it, and it is what a user wants who runs eq on an opaque window. The default,
  `terminal`, leaves the ground alone so a translucent terminal (the user's Zap runs at 67 %
  opacity, research 09 §2) stays translucent; only surfaces (status bar, chips, selection, tints,
  console panels) are painted.

### Colour depth: detection and fallback

1. `--colors` / `tui.colors` other than `auto` wins.
2. `NO_COLOR` set and non-empty, or `TERM=dumb` → `none` (today's `Paint.enabled` rule).
3. `COLORTERM` is `truecolor` or `24bit` → `24bit`. Inside tmux this is always set (tmux exports
   it to every pane) and always safe: tmux converts 24-bit colours to 256 or 16 itself when its
   own terminal cannot show them (research 09 §2). No `tmux info` subprocess, no terminfo.
4. `TERM` ends in `-direct` → `24bit`.
5. `TERM` contains `256color` → `256`.
6. Otherwise `16`.

Measured on the user's stack: `TERM=xterm-256color`, `COLORTERM=truecolor`, tmux with
`xterm-256color:RGB` → `24bit` end to end.

Per depth, each token resolves to (research 09 §1.4: pick the fallback by hand, do not convert
blindly):
- **24-bit**: the hex value. **256**: the nearest xterm-256 index by tmux's rule (real cube levels
  0/95/135/175/215/255, grey ramp when closer) — except where the table below gives an index by
  hand (the tints, which the cube would turn grey). **16**: the token's SGR from the table — the
  sixteen meanings of README "Colour" are kept (green boost, magenta cut, yellow warning, red
  failure, cyan accent, dim secondary); instrument hues have no 16-colour value and fall back to
  default/bold as today. **none**: no colour; bold, dim, underline and **reverse** carry state —
  a cell whose meaning is its background (the current tab, a chip, a flag, a solid bar cell,
  the curve crossing a bar) is drawn reverse-video instead.
- The meter gradient at 16 colours becomes three zones (green < −18, yellow −18…−6, red ≥ −6
  dBFS); at 256, ~7 visible steps.

### Motion

All within the 30 fps frame the daemon already sends; nothing adds a timer of its own except
where noted.
- **Peak hold**: per band, the peak tick holds 1.5 s (45 frames), then falls at 11.8 dB/s (IEC
  60268-10 Type I return, research 09 §3). Kept in the Model; `tui.peaks` off hides it. The side
  column's output peak does the same.
- **Edit flash**: the edited band's gain chip goes solid for 15 frames (today's
  `Watch.flashFrames`), then back through 3 blended steps over 9 frames (24-bit only; 256 and 16
  switch at once). The console fader cap turns `cap_sel` for the same time.
- **Note fade**: a message's last 15 of its 60 frames step from `text2` to `text3` in 3 steps,
  then it clears.
- **LIMIT**: lit while the daemon reports limiting and 10 frames after, so a one-frame limit is
  seen.
- **Look or palette switch** (`y`, `Y`): the front buffer is invalidated and the next frame is
  written in full.
- Nothing pulses or blinks.

### Bytes and CPU

Budget from M2, unchanged: at 120×40 on the Meter view, CPU ≤ 5.7 % and ≤ 4.5 KB a frame with
moving levels. Simulated (research 09 §4, 150 frames at 120×40; "stress" = every band jumps
every frame):

| Look, depth | Music | Stress | Full frame (start, resize, `y`) |
| --- | --- | --- | --- |
| classic, 16 | 543 B | 1 979 B | 9.1 KB |
| studio, 16 | 681 B | 2 078 B | 10.7 KB |
| studio, 256 | 934 B | 2 927 B | 17.8 KB |
| studio, 24-bit | 1 273 B | 3 957 B | 25.4 KB |
| console, 24-bit | 378 B | 1 914 B | 40.8 KB |

These hold only with the renderer rules below (a naive per-cell encoder writes 24 KB a frame in
24-bit stress):
1. **Pen tracking**: the renderer remembers the terminal's current SGR state across the whole
   frame and writes only the difference (`transition(pen, style)`); a reset (`0`) only when an
   attribute must go off.
2. **Style → bytes cache**: each distinct `(fg, bg, attrs)` at the current depth is encoded once
   into its byte string, kept in a dictionary cleared on a depth or palette change. The meter
   gradient is a precomputed table of one style per meter row per band state (normal, outside
   the focus), rebuilt on resize — btop's 101-string gradient table (research 09 §1.1).
3. **One colour per meter row**: the gradient is by height, so all ten bars of a row share one
   pen; the encoder sets it once per row.
4. **Solid cells as background-coloured spaces**: 1 byte instead of `█`'s 3, and no hairline gaps
   between rows.
5. **Moves**: a cursor move (`CUP`) per new row; within a row, the gap to the next changed run is
   either skipped with `CUF` (`ESC[nC`) or rewritten, whichever is fewer bytes.
6. Synchronized update brackets and one `write(2)` per frame, as M2 already specifies.

CPU: the curve is recomputed only when gains or the width change (1 600 filter evaluations at
120 columns); per frame the work is filling ~4 800 cells and one diff pass — no string
formatting of colours on the hot path.

### What M2 should know now

M2 is being built. To avoid a migration in M2b, M2's `Style` should already be
`fg: Color, bg: Color, bold, dim, underline, reverse`, with
`enum Color { case none, ansi(UInt8 /* 0–15 */), indexed(UInt8), rgb(UInt8, UInt8, UInt8) }`,
and the renderer should emit SGR through a per-style cache with pen tracking (rules 1, 2, 5
above). M2 itself keeps drawing only `.none` and `.ansi` — the same pixels as today.

- Measured on the user's stack before acceptance: the byte and CPU budget with music, OSC 11
  through tmux into Zap (decides whether `palette auto` can pick `paper`), braille and block
  glyphs line up in Zap at the user's font size.
- Accept: the user runs `eq watch` in each look (`y` cycles), with `--colors 256`, `16` and
  `NO_COLOR=1`, and every screen is readable; the mocks in `docs/design/tui/` are what they see.

Later milestones use the tokens from the start: M3 draws tabs, the instruments view and the
help overlay as mocked; M4 draws Tune as mocked.
