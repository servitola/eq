# eq — headless system-wide equalizer for macOS

Date: 2026-09-27. Status: approved in chat (Telegram topic «eqmac»), written down here.

## Why

servitola uses eqMac's free 10-band "Advanced" EQ with one hand-tuned curve
(32 Hz … 16 kHz, values below) for every output. eqMac 1.9.1 is closed source, ships a
HAL driver that needs `sudo` and a coreaudiod restart, phones home for its UI, and its
per-device "Super Presets" auto-switch is reported broken on macOS 26 (bitgapp/eqMac
#732, #1022). The open-source eqMac is frozen at v1.3.2 (2023) and no longer builds
against a current SDK.

Every open-source replacement found (core-eq, SystemEQ-for-Mac, OnlyEQ, GlassEQ,
iQualize …) is a menu-bar SwiftUI app with an icon, a popover and an updater. The
requirement here is the opposite: no icon anywhere, no window, no update prompts,
minimal CPU/RAM, the curve from the screenshot, and a separate curve per output device
(built-in speakers, Bluetooth speakers, headphones) that follows the active output
without ever dropping the EQ.

## What

One executable, `eq`, packaged as `EQ.app` (LSUIElement, no icon), in two roles:

- **daemon** — `eq daemon`, started by a LaunchAgent. Taps the system output mix,
  runs it through a 10-band graphic EQ, plays it back on the current default output
  device. Follows default-output changes and applies that device's curve.
- **CLI** — every other subcommand. Edits the config file; the daemon watches the file
  and applies changes immediately. No IPC.

Not in scope: any GUI, parametric bands, AutoEQ import, per-app mixing, spectrum,
input devices, Intel builds, notarization.

## Audio engine

Signal path (macOS 14.4+ process-tap API, no driver, no root):

```
all processes except self ──(muted global CATap)──▶ aggregate device { tap + real output }
    ──▶ IOProc: deinterleave → preamp → 10 peaking biquads per channel → interleave
    ──▶ real output device
```

- The tap is created with `CATapDescription(stereoGlobalTapButExcludeProcesses:
  [own PID])`, muted (`.muted`), so the original mix is silenced and only the
  processed copy is heard. Volume keys keep working: the hardware volume belongs to the
  real device inside the aggregate.
- Engine code is vendored from zollans/OnlyEQ (Unlicense): `ProcessTapEngine.swift`
  (tap + aggregate device + IOProc + Bluetooth/sample-rate handling +
  `TapInputSelection` topology logic), `AudioDeviceManager.swift` (device enumeration,
  default-output listeners, UID/name/transport), `BiquadFilter.swift` and
  `EQProcessor.swift` (RBJ cookbook peaking filters, vDSP). Spectrum analyzer, hardware
  volume writer and everything UI-related are dropped. Files keep a one-line header
  naming their origin and commit.
- EQ: 10 peaking filters at 32, 64, 125, 250, 500, 1k, 2k, 4k, 8k, 16k Hz, Q = 1.41
  (one-octave graphic EQ), gain −12 … +12 dB each, plus preamp −12 … +12 dB applied as
  a linear multiplier before the filters. Coefficients are recomputed on every config
  change and on every sample-rate change. Choosing vendored biquads over Apple's
  `AUNBandEQ`: the engine already hands us deinterleaved float channels, and calling
  `processor.process(channels:frameCount:)` is simpler than hosting an AudioUnit inside
  the IOProc.
- Buffer size: the daemon requests 256 frames (≈ 5 ms at 48 kHz; end-to-end ≈ 10 ms)
  on the aggregate and falls back to whatever size the device grants.

## Device following

- The daemon listens to `kAudioHardwarePropertyDefaultOutputDevice` and
  `kAudioHardwarePropertyDevices`. On a change it tears down the aggregate and rebuilds
  it on the new default output, then loads that device's profile.
- Bluetooth devices connect in two steps (device appears, then becomes default, and the
  sample rate may change a moment later). Rebuild is therefore retried up to 5 times
  with 1 s spacing until the IOProc reports frames flowing; a device that disappears
  mid-rebuild is not an error, the next default-change event restarts the sequence.
- The daemon never routes to its own aggregate device: if the default output is an
  aggregate whose UID starts with `com.servitola.eq`, it is ignored (stale aggregate
  from a crash) and destroyed.
- A device with no profile gets `default` and one log line
  `new device "<name>" (<uid>) — using default profile`.

## Config

`~/.config/eq/eq.json`, created by `eq init` with the screenshot curve:

```json
{
  "version": 1,
  "enabled": true,
  "default": { "preamp": 0.0, "bands": [4.8, 4.0, 4.2, 2.3, 0.0, -3.1, 0.0, 0.0, 3.1, 2.4] },
  "devices": {
    "<uid>": { "name": "MacBook Pro Speakers", "preamp": 0.0, "bands": [4.8, 4.0, 4.2, 2.3, 0.0, -3.1, 0.0, 0.0, 3.1, 2.4] }
  }
}
```

- `bands` is always exactly 10 numbers in the fixed frequency order above.
- Keys in `devices` are Core Audio device UIDs (stable per physical device; Bluetooth
  UIDs carry the MAC). `name` is informational and refreshed by the daemon when it sees
  the device.
- Validation: `version == 1`, gains within ±12, exactly 10 bands, `enabled` boolean.
  An invalid or unparsable file is rejected: the daemon keeps the last good config and
  logs the reason; the CLI refuses to write it and prints the reason.
- The daemon watches the file with a `DispatchSource` (vnode write/rename/delete) and
  reloads with a 100 ms debounce. Writers replace the file atomically (write temp +
  rename), which the watcher treats as a change.

## Status

The daemon writes `~/.cache/eq/status.json` on every state change and every 5 s:

```json
{ "state": "running", "device": { "uid": "…", "name": "JBL Big", "transport": "bluetooth" },
  "sampleRate": 48000, "profile": "device", "framesProcessed": 12345678,
  "enabled": true, "error": null, "pid": 4242, "updatedAt": "2026-09-27T10:00:00Z" }
```

`state` ∈ `starting | running | bypassed | no-permission | failed`. `profile` ∈
`device | default`. A status file older than 15 s means the daemon is dead.

## CLI

```
eq                       profile of the current output device (bands table, preamp, device)
eq init                  write the default config if none exists
eq set 64hz +4 1khz -3   set bands on the CURRENT device's profile (creates it from default)
eq set --device JBL …    same, for the device whose name contains "JBL" (case-insensitive,
                         must match exactly one known device or one profile)
eq preamp -1.5           preamp for the current (or --device) profile
eq flat                  all bands and preamp to 0 for the current (or --device) profile
eq copy --to AirPods     copy the current profile onto another device's profile
eq devices               known profiles + currently connected outputs, active one marked
eq on | eq off           enabled = true/false (bypass keeps the tap alive, passes audio through)
eq status [--json]       contents of status.json, plus a hint when state is no-permission
eq daemon                run the engine in the foreground (what the LaunchAgent starts)
```

Band names accept `32hz 64hz 125hz 250hz 500hz 1khz 2khz 4khz 8khz 16khz` (case-
insensitive, `k` optional as `1000hz`). Gains accept `+4`, `-3.1`, `0`. Out-of-range or
unknown band is an error and nothing is written.

"Current device" for the CLI is the daemon's device from `status.json` when fresh,
otherwise the system default output device queried directly.

## Packaging and install

- SwiftPM package (`swift-tools-version` 5.10, platform macOS 14.4), one executable
  target `eq`, one test target. Built with `swift build -c release`, arm64 only.
- `scripts/build-app.sh` assembles `build/EQ.app`: `Contents/MacOS/eq`, `Info.plist`
  with `CFBundleIdentifier com.servitola.eq`, `LSUIElement true`,
  `NSAudioCaptureUsageDescription`, no icon. Signed with the Developer ID identity when
  `CODESIGN_IDENTITY` is set (hardened runtime + `com.apple.security.device.audio-input`
  entitlement), otherwise ad-hoc with an identifier-pinned designated requirement (as
  OnlyEQ does) so the TCC grant survives local rebuilds.
- Why an app bundle for a daemon: the "System Audio Recording" TCC prompt and grant are
  attributed to a bundle with an Info.plist; a bare binary launched by launchd gets no
  prompt and fails silently.
- Homebrew: cask `eq` in `~/projects/homebrew-tap` — `app "EQ.app"`,
  `binary "#{appdir}/EQ.app/Contents/MacOS/eq", target: "eq"`, quarantine strip in
  `postflight_steps` like the other casks, `depends_on macos: :sonoma`, arm64. Published
  through `bin/publish-app.sh eq servitola/eq <version> build/EQ.app --hardened
  --entitlements …` from `bin/release-eq.sh` (shape of `release-claude-counter.sh`).
- LaunchAgent `~/projects/dotfiles/launchagents/com.servitola.eq.plist`: runs
  `/Applications/EQ.app/Contents/MacOS/eq daemon`, `RunAtLoad`, `KeepAlive`, log to
  `cron/logs/eq.log`. Installed through the existing dotfiles launchagent flow.
- No nightly job. There is no upstream to rebase; a release is `bin/release-eq.sh
  <version>` run by hand. Versions are semver tags (`v0.1.0`).
- Migration, done once by hand after the daemon is verified: quit eqMac,
  `brew uninstall --cask eqmac`, `sudo \rm -r /Library/Audio/Plug-Ins/HAL/eqMac.driver`
  followed by `sudo killall coreaudiod` (the user runs these), replace `cask "eqmac"`
  with `cask "servitola/tap/eq", trusted: true` in `homebrew/brewfile`.

## Error handling

| Situation | Behaviour |
|---|---|
| No System Audio Recording permission | tap creation fails; state `no-permission`; `eq status` prints "System Settings → Privacy & Security → Screen & System Audio Recording → enable EQ"; retry every 30 s |
| Default output disappears | listener fires; rebuild on the new default; audio continues on whatever macOS picked |
| Rebuild fails 5× | state `failed` with the OSStatus; keep listening, next device event retries |
| Config invalid | keep last good config; `error` in status carries the reason |
| Daemon crash | launchd `KeepAlive` restarts it; stale aggregate device is destroyed on start |
| Two daemons | second instance sees a fresh `status.json` with a live pid and exits 1 |
| Sample rate changes under a live tap | engine is restarted on the same device (coefficients are baked per rate); ~50 ms gap |

## Testing

- Unit (XCTest, `swift test`): config parse/validate/round-trip; band-name and gain
  parsing; profile resolution (device → default); `TapInputSelection.select` cases
  (kept from OnlyEQ); biquad coefficient sanity (0 dB gain → unity, symmetric ±gain);
  status-file freshness logic.
- Smoke, scripted in `scripts/smoke.sh` and run before every release: build, launch
  `eq daemon` in the background, wait for `status.json` `state == running`, run `eq`,
  `eq set 1khz -3`, assert the status `framesProcessed` grows and the daemon picked up
  the change, kill it.
- Listening test by servitola: speakers ↔ Bluetooth speakers ↔ headphones, EQ must never
  drop, each device keeps its own curve.
- Resource budget checked once on the smoke run: RSS ≤ 30 MB, CPU ≤ 3 % on one core
  while playing music.
