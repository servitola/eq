# eq v4 — `eq watch`: the equalizer, alive, in the terminal

Date: 2026-09-27. Status: approved in chat (option B). Deltas on top of v1–v3.

## Why

The ten sliders exist only as numbers. `eq watch` shows what the music does to them: a
live level per band, before and after the EQ, with the slider position drawn over it — the
old graphical equalizer, in our sixteen colours, in a terminal. `eq stream` gives the same
numbers as JSON lines for anyone who wants to draw their own.

## What the user sees

```
BE-RCA · 44.1 kHz · preamp -1.5 dB                                    LIMIT
  █     █                                                 (12 rows)
  █     █     █                 ▬
  █ ▬   █     █     █           ░
  █     █ ▬   █ ▬   █ ▬   █     ░     ░           ▬     ▬
  ░     █     █     █     █     █ ▬   ░     ░ ▬   █     █
  ░     ░     ░     ░     ░     ░     ░     ░     ░     ░
  32Hz  64Hz 125Hz 250Hz 500Hz  1kHz  2kHz  4kHz  8kHz 16kHz
  +4.8  +4.0  +4.2  +2.3  +0.0  -3.1  +0.0  +0.0  +3.1  +2.4
```

- Each column is a band. `█` in the gain's ink (green boost / magenta cut / dim zero) is the
  **output** level after the EQ; `░` dim is where the **input** level reaches above the output
  (a cut) — and when the output exceeds the input (a boost) the coloured part simply stands
  taller. Levels are dBFS over −60…0 mapped to the rows, with a fast attack (~10 ms) and a
  slow release (~300 ms) so the bars fall like meters.
- `▬` at the row of the band's gain (−12…+12 dB → rows) is the slider position.
- Header: device, sample rate, preamp; `LIMIT` in yellow while the limiter is reducing gain.
  Footer: the labels and gains rows exactly as `eq` prints them.
- Redraw ~30 times per second; the alternate screen is used and restored; `q` or Ctrl‑C
  exits. Needs a TTY at least 64 columns wide and 16 rows high, else a plain error.
- `eq watch` refuses without colour? No — it works in monochrome too (glyphs carry the
  shape); colour follows the same rules as everywhere.

## `eq stream`

JSON lines on stdout at ~30 Hz until Ctrl‑C; one document per line:

```json
{"t":1790500000.123,"device":"BE-RCA","rate":44100,"in":[-32.1,…10],"out":[-28.0,…10],
 "peak":-6.2,"limiting":false,"gains":[4.8,…10],"preamp":-1.5,"enabled":true}
```

`in`/`out` are per-band dBFS (−60 floor), `peak` the post-chain stereo peak in dBFS.
`--json` is implied; there is no text form. Exit codes: 0 on Ctrl‑C, 1 when the daemon is not
running or predates v4 (no socket).

## How the numbers are made

- **Band meter** (audio thread, only while someone is connected): the stereo input is summed
  to mono, then ten RBJ band-pass biquads at the band centres (Q 1.41) run on the mono
  input and, separately, on the mono output of the chain; each band keeps a peak envelope
  (attack coefficient for 10 ms, release for 300 ms at the current sample rate). Twenty
  biquads on one mono channel per callback — well under 1 % of the callback's budget.
  Everything is pre-allocated; the meter is toggled by one `Bool` the render thread reads
  once per callback. When nobody is connected the meter code does not run at all.
- **Meter server** (daemon main queue): a Unix domain socket at `~/.cache/eq/meter.sock`
  (next to `status.json`; `EQ_STATUS`'s directory decides). Listening starts with the daemon;
  the file is removed on exit and any stale file is removed at start. Each accepted client
  gets one JSON line per tick from a 30 Hz `DispatchSourceTimer` that runs only while
  `clients > 0`. A client whose write fails is dropped. Connect/disconnect log one line each
  (`meter: 1 client`, `meter: 0 clients`). The socket carries no commands — read-only.
- **Client** (CLI): connects, reads lines, renders or prints. `watch` also reads the keyboard
  in non-canonical mode for `q`.

## Footprint

Zero cost while nobody watches: no timer, no meter DSP, one idle listening socket. While
watching: ~30 small writes per second to a local socket and two extra biquad banks — the
measured CPU of `eq watch` itself (a redraw of 14 lines at 30 Hz) is expected around 1–2 %
and belongs to the CLI process, not the daemon.

## Not in scope (v4)

Interactive editing from the watch screen (option C), FFT spectrum, per-channel meters,
history/scrolling, a web view.

## Testing

- Unit: band meter on a 1 kHz sine at −6 dBFS → band 5 within 1 dB of −6, the neighbouring bands
  about 7 dB lower per octave (Q 1.41), at least 12 dB at one octave, 18 at two, 21 at three or
  more; release behaviour (levels fall after silence); the frame renderer is a
  pure function `Watch.frame(...) -> [String]` tested for row count, marker position, and no
  escape codes when colour is off; the JSON line encodes/decodes round-trip; the meter server
  accepts a client over a temp socket path, sends ≥ 3 lines in 200 ms from an injected level
  source, and turns the source off when the client disconnects.
- Smoke: `eq stream` against the smoke daemon for 2 s yields ≥ 20 lines with 10-element arrays;
  the daemon log shows `meter: 1 client` then `meter: 0 clients`.

## v4.1 — feedback from the first live look (2026-09-27)

- **Any width, any height, no error.** Column width `w = clamp((cols - 2) / 10, 3, 8)`; ten
  columns when `cols ≥ 32`, otherwise as many as fit (the lowest bands first) and a dim note
  `… widen for all bands`. Labels: full (`32Hz`) when `w ≥ 6`, short (`32`, `1k`) otherwise.
  Meter rows = terminal rows − 5 (header, live row, labels, gains, one spare), minimum 4.
- **Resize.** The size is re-read every frame (`TIOCGWINSZ`); when it changes the screen is
  cleared and redrawn. No `SIGWINCH` handler needed.
- **The number that actually came out.** A **live row** directly under the bars: each band's
  current output level in dBFS as an integer (`-32`), painted like the bar; `·` when at the
  floor. The header ends with `peak -6.2 dB` (post-chain stereo peak), then `LIMIT` when the
  limiter is working.
- **Two shades per colour.** Bars use the normal SGR colour up to −6 dBFS and the bright
  variant (SGR 90–97) above it — hot signal reads hotter. The slider marker uses the bright
  variant when |gain| > 6 dB. Still the sixteen terminal colours, nothing else.
- **Smoother motion.** The top cell of each bar is a partial block (`▁▂▃▄▅▆▇█`) for the
  fraction of a row the level reaches, so a bar moves in eighths of a row, not whole rows.
  The slider marker is `╴─╶` narrow… keep `▬` but only over the bar's column, never wider than
  the cell.
- Everything else unchanged: `q`/Ctrl‑C, alternate screen, `eq stream` numbers.

## v4.2 — zone hints: where each instrument lives

A tuning aid: under the bands, a block of spans shows which bands carry which part of a mix,
so "the voice sounds thin" becomes "look at 1k–4k". Toggled with `z` in `eq watch` and on at
start with `eq watch --zones`; off by default so the plain view stays calm.

```
  32Hz  64Hz 125Hz 250Hz 500Hz  1kHz  2kHz  4kHz  8kHz 16kHz
  +4.8  +4.0  +4.2  +2.3  +0.0  -3.1  +0.0  +0.0  +3.1  +2.4
  kick   ━━━━━━━━━━━━━━━━━
  bass   ━━━━━━━━━━━━━━━━━━━━━━━
  guitar             ━━━━━━━━━━━━━━━━━━━━━━━━━
  voice                    ━━━━━━━━━━━━━━━━━━━━━━━━━
  snare              ━━━━━━            ━━━━━━━━━━━━
  cymbals                                    ━━━━━━━━━━━━━━━━━━
  air                                                    ━━━━━━
```

- One row per zone; the name (dim) on the left in the margin, the span `━` under the band
  columns it covers, from the centre of the first band to the centre of the last.
- Zones (band indices into 32…16k), chosen from common mixing references, coarse on purpose:

| Zone | Bands | Why |
| --- | --- | --- |
| sub | 32, 64 | felt more than heard; rumble |
| kick | 64, 125 | thump and punch of the bass drum |
| bass | 64, 125, 250 | bass guitar body and definition |
| warmth / mud | 250, 500 | fullness; too much turns muddy |
| guitar | 250 … 2k | body to bite of guitars and keys |
| voice | 500 … 4k | vowels at 500–1k, intelligibility and presence at 2–4k |
| snare | 250, 4k | body and crack |
| cymbals | 4k, 8k, 16k | attack and shimmer of hats and cymbals |
| sibilance | 4k, 8k | the "s" of a voice; a cut here tames harshness |
| air | 16k | sparkle and space |

  The watch shows seven of these by default (sub, kick, bass, guitar, voice, cymbals, air);
  `z` pressed again cycles to the full list, then off.
- Span colour: the band's live level ink where that band is the loudest in the zone right
  now, dim elsewhere — the eye goes to the zone that is doing the work.
- Needs `rows ≥ meterRows_min + 5 + zoneRows`; when the terminal is too short, the meter
  shrinks first (to its 4-row minimum), then zones drop from the bottom of the list.
- `eq zones` (no daemon needed) prints the same block once under the current curve, for a
  quick look without music; `--json` gives `[{"name","bands":[…],"why"}]`.

## v4.3 — tune from the keyboard, with a hint that can be dismissed for good

`eq watch` becomes the place where you tune, not only look.

| Key | Action |
| --- | --- |
| `1` … `9`, `0` | raise band 32 Hz … 16 kHz by 0.5 dB (`0` is the tenth band, 16 kHz) |
| Shift + the same key | lower it by 0.5 dB — `! @ # $ % ^ & * ( )` on a US layout, `! " № ; % : ? * ( )` on a Russian one |
| `+` / `-` | preamp ±0.5 dB |
| `z` | zones: off → compact → all → off |
| `?` | show the hint again |
| `x` | hide the hint for good |
| `q`, Ctrl‑C | exit |

- An edit changes the **current device's** profile (same resolution as `eq set`: the daemon's
  device from a live status, else the default output), clamps to ±12 dB, and saves through
  `ConfigStore` right away; the daemon reloads within ~0.1 s and the slider marker moves on the
  next frame. The edited band's column label flashes bold for ~0.5 s.
- **Hint box.** On start, unless dismissed, a small box sits in the top-right corner over the
  empty part of the meter:
  ```
  ┌ tune ─────────────────────┐
  │ 1…0   band up   0.5 dB    │
  │ ⇧1…0  band down 0.5 dB    │
  │ + −   preamp              │
  │ z     zones   ? this hint │
  │ x     hide this for good  │
  │ q     quit                │
  └───────────────────────────┘
  ```
  Dim border and keys, plain text. It hides by itself after 8 s or on any key; `?` brings it
  back; `x` hides it and writes `~/.config/eq/watch-hint-off` (an empty marker file), after
  which it never appears on start — `?` still shows it. Too-narrow terminals (box wider than
  half the width) skip the box and show one dim line under the gains row instead:
  `1…0 up · ⇧ down · +/− preamp · z zones · ? help · q quit`.
- Nothing is written when the key is not a mapped one; unknown keys are ignored.
